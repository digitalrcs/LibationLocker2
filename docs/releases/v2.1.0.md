# Libation Locker 2 Server Edition v2.1.0

Usage & History now uses locally bundled Apache ECharts 6.1.0: consumption line/area charts, usage and reorder bars, and stepped stock history. Includes date zoom, theme-aware tooltips, expanded views, accessible descriptions, and responsive mobile sizing. Empty-state handling and zero-usage weeks are corrected.

## Downloads

- **LibationLocker2-2.1.0-iis-upgrade-win-x64.zip**: recommended for an existing Windows x64 IIS installation. Contains application files at the ZIP root, including the executable and DLL. Excludes every `web.config` and `appsettings*.json` file so existing server configuration is preserved. Extract into a staging folder first.
- **LibationLocker2-2.1.0-app-win-x64.zip**: full framework-dependent Windows x64 application under `app/`, plus database scripts and documentation. Includes generic configuration for a new installation; do not overwrite existing production settings with it.
- **LibationLocker2-2.1.0-source.zip**: source snapshot matching the release tag.
- **SHA256SUMS.txt**: SHA-256 checksums for all ZIP assets.

The application requires the .NET 8 ASP.NET Core Runtime and SQL Server. IIS requires the .NET 8 Hosting Bundle and a 64-bit application pool using No Managed Code. The upgrade ZIP is not a standalone new installation.

## Upgrade an existing IIS server

1. Back up the site's directory and SQL Server database. Record the IIS physical path and application pool.
2. Confirm that your connection string is configured in an existing `appsettings.json`, `appsettings.Production.json` when running in Production, or the `ConnectionStrings__LibationLocker` environment variable. `appsettings.Local.json` is not automatically loaded by this application.
3. Verify that you can sign in with a database-backed administrator. See the legacy-login note below if you previously relied on a built-in account.
4. Stop the site's application pool. Extract the **iis-upgrade** ZIP to a separate staging directory, then copy its contents over the existing site files. Do not delete the destination or use a mirror operation.
5. Preserve existing `web.config`, all `appsettings` files, environment variables, Data Protection keys, uploads/images, exports, and logs. The package contains no real inventory data or credentials.
6. Start the application pool, reload the site, and verify sign-in, inventory, recipes, Usage & History, and AI availability. CSS and JavaScript references include cache-busting versions; hard-refresh if a proxy or browser retains old assets.

There are **no database migrations from v2.0.0 to v2.1.0**. Older installations must have the existing schema scripts through `004_ItemHistory.sql`; review their current migration state first. Do not run demo-data or database initialization scripts against an existing production installation just to update the charts.

### Legacy built-in administrator

The public code no longer includes a hard-coded login. Existing database-backed accounts remain supported. If the old built-in account was your only login, configure these settings privately in the IIS application's environment before upgrading:

- `LibationLocker__BootstrapAdmin__Enabled=true`
- `LibationLocker__BootstrapAdmin__Email` set to your administrator email
- `LibationLocker__BootstrapAdmin__Password` set to a new, long, unique password

Bootstrap login also requires the database setting `Auth.AllowDefaultAdmin` to remain enabled. Create a permanent database-backed administrator, verify that account works, then disable bootstrap access and remove its credentials. Do not put credentials in release assets or public source control.

## Installation from scratch

Use the full application package and follow `docs/database.md`, `docs/configuration.md`, and `docs/deployment-iis.md`. The bundled default connection string targets LocalDB for development and must be configured for your server. Point IIS at the extracted `app` directory.
